# 文件资源管理器统一悬浮提示

## 目标与环境

用户于 2026-10-09 要求修复备注 Tooltip 与 Obsidian 官方 Tooltip 重叠的问题。测试环境为 Obsidian 1.14.4、Total Commander 11.58，测试 Vault 为 `D:\Libraries\Obsidian\Demo\`，真实应用验收由用户手动完成。

有备注时显示一个统一悬浮提示，上方显示纯文本备注，下方保留当前对象原有的官方提示信息。文件与文件夹的官方信息须分别核实，不能凭印象自行替代。

悬停约 200 毫秒后显示，不等待官方提示的较长延迟；内容就绪后一次呈现，不先显示再合并，不因第二个提示出现而跳动或自动避让。有备注时只抑制当前条目的原官方 Tooltip，无备注时保持官方行为。

## 已核实的现有实现

- `src/ui/file-tree-tooltip.ts` 在文档上委托 `mouseover`，进入条目后立即调用备注服务，读取成功就创建独立的 `.descript-ion-tooltip`。
- 现有实现既未设置 200 毫秒延迟，也未读取官方提示信息或抑制当前条目的官方提示。两套提示能同时出现，与用户报告一致。
- 现有备注服务每次读取实际存储，返回备注或原因；本次沿用它，不改动备注格式及写入行为。
- 现有请求序号与插件注册清理可作为快速切换、离开条目和卸载时取消的基础。

## 官方公共接口

[Obsidian 官方类型定义](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)及本项目安装的类型提供：

- `setTooltip`：设置悬浮文本，公开于 1.4.4。
- `TooltipOptions.delay`：设置延迟，公开于 1.4.11。
- `displayTooltip`：手动触发提示，内容可为字符串或 DocumentFragment，公开于 1.8.7。

这些接口没有公开文件树原生提示的内容生成与单条目取消契约。具体接入须以本机 1.14.4 程序资源为依据；若采用较新的公共接口，须同步最低版本声明。

## 收敛后的实现方案（已确认）

1. 在小型文件树兼容层中识别当前条目和所属文件资源管理器，在原生委派处理之前暂缓当前备注对象的 pointerover。根目录、descript.ion 及其他界面条目直接放行。
2. 同时开始读取实际备注存储与约 200 ms 的悬停计时。读取有备注或失败原因时，准备上方纯文本备注/原因和下方原生字段、当前语言文案；标题截断规则沿用目标版本。两者就绪且停留时间达标后，以一个完整 DocumentFragment 调用公开 displayTooltip，一次显示。
3. 成功读取且无备注时，调用当前文件树原有处理，恢复官方提示及交互；允许原有显示延迟额外加上本次读取耗时。不在后台预读或缓存是否存在备注。
4. 有备注/错误分支补回文件原有 hover-link 参数，保留 Page preview。仅接管当前对象提示，不全局屏蔽官方 Tooltip，也不观察已显示的官方 Tooltip 再追加合并。
5. 离开条目、滚动、切换目标与禁用时使待显示请求失效；清理计时器、插件提示和注册监听。无先显示后合并或因另一提示出现而重新定位的过程。
6. 更新最低版本及说明文档，运行类型检查、测试、lint、生产构建；安装三个产物到测试 Vault，真实 UI 验收由用户完成，重点验证文件/目录信息、200 ms、无备注恢复、Page preview、快速切换和禁用清理。
