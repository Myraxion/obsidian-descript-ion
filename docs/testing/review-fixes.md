# 核心实现审查修复

本次修复对应核心审查的五项问题，不包含孤立备注清理。

## 自动化回归

- `tests/storage-safety.test.ts`：真实文件系统中注入部分写入失败，验证原备注字节、隐藏属性和临时文件清理。
- `tests/comment-service.test.ts`：保留 Windows 隐藏文件更新、新建隐藏文件和只读拒写的既有验证；临时目录统一位于生成目录 `.test-build`，避免系统临时目录的沙箱重命名限制。
- `tests/lifecycle-races.test.ts`：验证源/目标父目录移动时排队任务跟随新路径，读取/写入准备期间移动会明确停止，目录删除后不重建元数据，以及成功保存/删除后通知显示刷新。
- `tests/target-state.test.ts`：验证删除对象能被垃圾回收，祖先目录重命名后返回原路径仍使旧编辑状态失效，兄弟目录目标不受影响。测试运行器启用 `--expose-gc`。

完整测试使用 `npm test`；单文件可运行 `node scripts/test.mjs tests/lifecycle-races.test.ts`。

## UI 验证

在模拟 Obsidian UI 环境、真实业务服务和可控存储下，已验证：

1. 无 Vault 文件事件时，从右键编辑器保存新备注，状态栏仍会刷新。
2. 状态栏点击等待读取时触发预定的展示刷新，编辑器正常打开。
3. 禁用插件后，刷新通知不再安排状态栏定时任务。

以上是受控 UI 验证，未替代实际 Obsidian/Total Commander 验收。实际应用回归应检查：

1. 在当前活动文件的右键菜单中添加、修改和删除备注，状态栏自动更新。
2. 切换文件后立即点击状态栏，编辑器正常打开且目标正确。
3. 连续移动文件及其源/目标父目录，检查备注随排队任务迁移；遇到正在维护的目录变化时显示停止同步提示。
4. Windows 中更新隐藏的备注文件，确认成功后仍为隐藏文件；只读文件拒绝更新且内容保持不变。

写入通过同目录临时文件替换原文件；Windows 替换期间会暂时清除目标的隐藏属性，完成或失败后恢复。跨目录迁移仍按既有 ADR 先写目标再清理源，不承诺跨文件事务。
