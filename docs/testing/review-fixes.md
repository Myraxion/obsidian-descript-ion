## UI 验证

在模拟 Obsidian UI 环境、真实业务服务和可控存储下，已验证：

1. 无 Vault 文件事件时，从右键编辑器保存新备注，状态栏仍会刷新。
2. 状态栏点击等待读取时触发预定的展示刷新，编辑器正常打开。
3. 禁用插件后，刷新通知不再安排状态栏定时任务。

以上是受控 UI 验证，未替代实际 Obsidian/Total Commander 验收。实际应用回归应检查：

1. 在当前活动文件的右键菜单中添加、修改和删除备注，状态栏自动更新。
2. 切换文件后立即点击状态栏，编辑器正常打开且目标正确。
3. 连续移动文件及其源/目标父目录，检查备注随排队任务迁移；遇到正在维护的目录变化时显示停止同步提示。
4. Windows 中更新隐藏的备注文件，确认成功后仍为隐藏文件；只读文件拒绝更新且内容保持不变。

写入通过同目录临时文件替换原文件；Windows 替换期间会暂时清除目标的隐藏属性，完成或失败后恢复。跨目录迁移仍按既有 ADR 先写目标再清理源，不承诺跨文件事务。

## 统一备注文件提交契约（2026-10-11）

存储 mutation interface 收拢为 `commit(path, bytes | null, check)`，写入完整字节或删除备注文件都必须等待提交检查。备注操作继续负责格式、编辑快照与目标身份校验，存储 adapter 负责准备和提交；检查异常原样传递，保留既有 stale 与迁移失败的错误分类。

- `tests/fixtures/memory-storage.ts`：普通备注操作测试与竞态测试共用一个 adapter，写入与删除都执行检查。
- `tests/storage-contract.test.ts`：对内存 adapter 与真实磁盘支持的 Vault adapter 运行同一组契约测试，验证异步检查完成前不修改文件、检查拒绝时原字节保留及原错误传播。
- `tests/lifecycle-races.test.ts`：新增最后条目编辑删除期间目标变化、维护删除期间源目录移动、跨目录迁移清源删除期间目录移动的回归。清源停止后保留已写目标与源记录，符合 ADR-0002。

自动验证：`npm test` 的 76 项测试通过，`npm run build` 与 `npm run lint` 通过。既有真实磁盘测试继续验证 Windows 隐藏/只读属性、部分写入失败及目录移动后的暂存清理。

删除仍由 Obsidian adapter 的 `remove` 完成，检查发生在调用它之前，不承诺在其内部异步步骤后再次检查。保存开始时的备注文件字节比较保持原范围，不增加暂存后的重读、外部锁或跨文件事务。本次未运行实际 Obsidian/Total Commander 回归。

## 集中备注维护任务执行规则（2026-10-13）

`src/comments/mutations.ts` 集中拥有保存、删除与维护的共用修改队列，以及维护任务的登记、开始、失效和释放。具名入口在事件到来时同步影响已有任务，随后登记并排队；执行回调开始时获得只读路径快照与检查函数。`src/comments/paths.ts` 提供共享的只读路径表示，取代调用者和维护逻辑之间的可变路径别名。旧 `maintenance-paths.ts` 的行为并入 mutations module。

`tests/mutation-execution.test.ts` 通过原有备注操作的公开 interface 验证：

- 保存先于维护时，两条备注均保留；维护先于旧会话保存时，保存返回 `stale_file`，不会覆盖维护结果。
- 保存暂停期间，已排队的维护立即跟随目录移动；普通读取不等待修改队列。
- 直接移动或删除备注文件会使排队中或已经开始的维护立即失效，不重建旧备注文件。
- 失效任务和直接备注文件操作完成后，后续有效维护继续执行。

原有 lifecycle races、存储契约与真实文件系统保护测试继续保留。格式规则、通知位置、错误代码、先目标后源的迁移顺序及上一轮提交保障范围保持不变。本次未运行实际 Obsidian/Total Commander 回归。

自动验证：`npm test` 的 83 项测试通过，`npm run build`、`npm run lint` 与 `git diff --check` 通过。

## 收拢备注编辑器生命周期（2026-10-13）

`src/ui/comment-editor.ts` 统一拥有两个入口的异步打开、有效性检查、读取失败提示、弹窗登记/释放和卸载关闭。右键请求独立完成；状态栏只接受最新的待完成编辑请求，已打开的弹窗可以并存。读取后统一核对原对象与路径，状态栏额外核对活动对象。状态栏显示请求与刷新调度仍独立，显示刷新不会取消编辑打开。

`CommentModal` 标记关闭状态。已发起的保存/删除继续完成，但关闭后不再更新消息、按钮、通知或再次关闭弹窗；成功修改仍通过原有备注操作通知刷新状态栏。成功提示依据本次提交文本；失败保留草稿，过期或只读时阻止再次提交，其余失败可重试。

`tests/editor-lifecycle.test.ts` 与 `tests/editor-submit.test.ts` 新增 29 项持续回归，执行真实注册入口、共享编辑 module 与弹窗按钮/快捷键回调，并使用真实备注操作和既有内存存储 adapter。`tests/fixtures/obsidian-ui.ts` 仅提供受控 Obsidian UI 平台；测试打包时通过 alias 替换运行时 `obsidian`，生产构建仍使用实际 Obsidian。
